# RSI v1 之后的改进尝试与失败记录（2026-09 日最高值）

> 本文只记录 **v1 之后的增量实验**。v1 / v2 的 canonical 产物没有被覆盖，文件校验值见文末。
> 评分口径：H1 = 113 个已观测站-日；H3 = 309 行（103 个三天全观测窗口 × 3 天）。
> 主指标 MAE；同时报告 RMSE / W-MAE / W-RMSE / PRE。除非特别说明，显著性均为 2026-09 上的配对检验。

## 0. 结论先行

1. **v1 仍然保留，未被任何实验覆盖**：H1 MAE **1.747**（raw Chronos-2 为 1.841）；H3 v1 MAE **2.423**。
2. **目前唯一稳定、且统计显著的改进是 H3 v2**：MAE **2.351**，相对 H3 v1 的配对差 0.072，bootstrap 95% CI **[0.011, 0.137]**，p≈0.02。
3. **H1 找到了一个数值和统计上都更好的候选 v1.1**：在线逐站门控 + 一步偏差修正，MAE **1.689**，相对 v1 配对差 0.058，bootstrap 95% CI **[0.008, 0.113]**，p≈0.019。但它是在 2025-09 dev 上选参后一次性迁移到 2026-09，且 dev 内部选参不稳定；因此**作为候选保留，不替换 v1**。
4. 其余 10 余种 2026 agentic time-series 机制（专家集成、验证集选 context、Hedge、RAF 检索、修正上限、LinUCB、相似日选择、残差校准、变换搜索、H3 门控）**全部没有超过 v1**，详见第 3–4 节。
5. 关键边界：v1 与其实际底座 `raw_point`（v1 选中的模型，绝大多数为 chronos2）的“逐样本完美开关”上限是 **1.690**；v1.1 的 1.689 已经贴住这个上限。若把 raw 固定为 chronos2，开关上限是 1.664。也就是说，**继续在 {v1, raw} 之间做门控/修正已经没有空间**，下一步必须引入新信息源。

## 2. 当前比 v1 更好的结果

### 2.1 H3 v2：唯一稳定显著的改进

- 配对差（v1−v2，正值表示 v2 更好）：**0.0724**。
- bootstrap 95% CI：**[0.0113, 0.1371]**，p≈0.020。
- 逐站 MAE：jiangjunyan 0.987、meichengmatou 1.518、yanlingwu 2.260、yanziling 4.337；相对 v1 四站全部改善。
- 结论：**可以正式作为 v1 的 H3 替代版本**。本文后续不再重复讨论。

### 2.2 H1 v1.1 候选：在线逐站门控 + 一步偏差修正

#### 策略定义（完全因果）

对每个站按 origin 顺序滚动：

1. 维护两个累计已实现误差：`E_v1 = Σ|v1−actual|`、`E_raw = Σ|raw−actual|`。
2. 当前 origin 选择基础预测：
   - 若 `E_raw − E_v1 > margin`，用 v1；
   - 否则用 raw。
   - 当前样本的真值不参与本次选择，只在此后进入累计误差。
3. 用最近 `k` 次“所选基础”的带符号误差均值 `b` 做修正：
   `point = base − λ·b`。
4. 超参数只在 **2025-09 dev** 上选：`margin ∈ {−0.5,−0.2,−0.1,−0.05,0}`、`k ∈ {1,2,3,5}`、`λ ∈ {0,0.05,…,0.5}`，共 160 组。
   dev 最优为 **margin=−0.5, k=1, λ=0.1**。

#### 结果

|---|---:|---:|---:|---:|---:|---:|
| RSI v1 | 113 | 1.747 | 2.751 | 2.077 | 3.361 | 0.152 |
| **v1.1 dev-selected** | 113 | **1.689** | 2.744 | 2.008 | 3.363 | 0.134 |
| raw Chronos-2 | 113 | 1.841 | 2.927 | 2.223 | 3.593 | 0.152 |
| 完美 v1 / raw_point 逐样本开关（oracle，raw_point 为 v1 实际选中的底座） | 113 | 1.690 | — | — | — | — |

逐站（MAE）：

| 站 | v1 | v1.1 | 启用 v1 的比例 |

- 配对差（v1−v1.1）：**0.0583**。
- bootstrap 95% CI：**[0.0076, 0.1129]**；t 检验 p=0.033；Wilcoxon p=0.036。
- 2025-09 dev：v1 11.300 → v1.1 11.281（仅改善 0.020）。
- 时间前后半段均改善：前半 1.631→1.572，后半 1.874→1.816。

#### 为什么仍然只作为候选

- dev 上的改善只有 0.020，而 dev 的 MAE 量级是 11.3；**这 0.02 本身在噪声内**。
- 160 组配置中有 41 组落在 dev 最优 +0.05 MAE 以内；换句话说，dev 几乎无法区分这些配置。
- dev 内部前后半段选出的最优配置不同：前半选 `λ=0`，后半选 `margin=0,k=3,λ=0.3`。选参不稳定。
- 因此 1.689 的显著性可以说明“这一次迁移有效”，但不足以说明“这个策略在任意月份都有效”。**需要 2027-09 或更多月份的外部验证**。

## 4. 逐项失败记录

### 4.1 专家集成：弱专家把强专家拉低

**做法**：把 chronos2、timesfm3、seasonal_naive 的 H1 点预测做等权、逆 MAE 权重、softmax 权重集成；再把 v1 的 fusion delta 加到集成结果上，模拟“只替换底座”的效果。

**结果**：

| 集成方式 | base MAE | + v1 fusion delta |
|---|---:|---:|
| 等权 | 5.369 | 5.493 |
| dev 逆 MAE 权重 | 1.943 | 1.834 |
| softmax | 1.935 | — |
| chronos2 + timesfm3 固定 0.5 | 1.858 | 1.764 |
| 仅 chronos2 | 1.841 | 1.757 |
| 滚动专家 Hedge + delta | — | 1.859–1.909 |

**失败原因**：2026-09 上 chronos2 明显强于另外两个专家，且三者高度同质（都只看蓝藻历史）。集成没有提供互补信息，只是把 chronos2 拉向更弱的预测。FairAMO 的结论——编排收益来自互补性、冗余成员会抵消收益——在这里完全成立。

H3 同样失败：chronos2 + timesfm3 0.5 混合 2.433，差于 v2 的 2.351。

### 4.2 验证集选 context：dev 最优不迁移

**做法**：在 2025-09 上对每个站搜索 context ∈ {7,14,28,60,120}，选 MAE 最低的长度；应用到 2026-09。

**结果**：2025-09 选出 `jiangjunyan 7 / meichengmatou 7 / yanlingwu 28 / yanziling 120`；2026-09 MAE **1.892**，差于固定 28 天的 **1.841**。

**失败原因**：context 长度是典型的“验证集噪声开关”。2025-09 的序列形态（高位、秋季回落）与 2026-09（低位、突发峰值）不同，dev 上一个站的 0.1–0.3 MAE 差异无法迁移。逐站 2026 结果：1.255 / 1.452 / 1.694 / 3.084，其中 jiangjunyan 的 7 天和 yanziling 的 120 天都没有带来预期收益。

### 4.3 在线 Hedge 学修正系数：修正本身是好的，收缩反而有害

**做法**：把 v1 的 fusion 修正写成 `final = raw + λ·(v1−raw)`，用指数权重在线学习 λ ∈ {0,0.25,0.5,0.75,1}，按过去误差更新。

**结果**：Hedge 1.773（η=0.5）到 1.793；固定 λ=1（即完整 v1）为 1.747。λ<1 全部更差。

**失败原因**：v1 的修正在平均意义上是对的（尤其 yanziling 的大幅上调），在线损失噪声让 Hedge 过早收缩，把真实增益也一起收掉。这个结果反过来验证了“v1 的 fusion 不是方差，而是方向性增益”。

### 4.4 RAF 检索增强：检索到的未来不够准

**做法**：对每个 origin，用近 3 日蓝藻 + 当日天气的标准化距离，从 2024–2025 同站历史中检索相似日，取其后 1 天的实际值作为“检索未来”；尝试直接使用、实例归一化后对齐、与 chronos2 按权重混合。

**结果**：

| 方式 | MAE |
|---|---:|
| 直接检索 | 3.984 |
| 检索 + 水平对齐 | 2.379 |
| 对齐后与 chronos2 混合 w=0.05 | 1.845 |
| 对齐后 w=0.10 | 1.850 |
| chronos2 | 1.841 |

**失败原因**：同站历史相似日只能提供“幅度先验”，不能提供“明天会不会爆发”的时序信息；对齐后仍有 2.379 的误差，任何正权重混合都把 chronos2 拉差。检索增强在长序列、多变量、强周期数据上更有效；本数据的日尺度突发峰值使相似日检索的信噪比很低。

### 4.5 H1 修正上限：yanziling 的大修正正是收益来源

**做法**：把 H3 v2 的“修正量 ≤ c×原始区间宽”搬到 H1，c ∈ {0.02,0.03,0.05,0.08,0.1,0.2,0.5,1.0}；另测只限制上修/只限制下修。

**结果**：c=0.02 → 1.824；c=0.03 → 1.816；c≥0.05 → 1.799；不加 cap → 1.747。上修/下修非对称 cap 的最好结果也是 1.747（等于不加）。

**失败原因**：H1 的增益集中在 yanziling 的少数大幅修正上；这些修正的绝对量大，但方向正确。用 H3 的“小步修正”先验去约束 H1，会把最有价值的修正截掉。**H1 和 H3 的最优修正幅度不同，不能共用同一个 cap。**

### 4.6 LinUCB 上下文赌博机：26% 的切换是净损失

**做法**：把 {v1, raw} 当作两个 arm，特征为近期误差、天气、站点 one-hot、时间；LinUCB 在每个 origin 选择 arm，reward = −|误差|/站内尺度。

**结果**：MAE **1.789**；约 26% 的 origin 切到 raw，切换后的净损失大于收益。

**失败原因**：113 个决策点、4 个站，每个站只有约 29 个反馈；LinUCB 的探索成本高于可获得的收益。与规则门控（1.724）相比，学习型策略没有更好，说明“是否用 v1”这个二值决策本身信息量很低。

### 4.7 相似条件/regime 选择：只比 v1 好 0.003

**做法**：TimeRSI 式“相似条件下选择历史最优候选”。按近 3 日蓝藻 + 当日天气的标准化距离，检索 k 个历史日，在每个 regime 内选择候选（v1、raw、timesfm3、seasonal、v1-cap 等）。

**结果**：最好的配置是 `pooled=False, k=40, temp=1.0`，MAE **1.750**；其余配置 1.85–2.02。相对 v1 仅好 **0.003**，远小于 113 样本的置信区间宽度。

**失败原因**：regime 特征（近 3 日蓝藻+天气）不足以区分“明天 v1 会不会错”；k=40 时每个 regime 的样本已经覆盖大部分月份，退化成全局选择。

### 4.8 残差校准器：dev 上选出的模型在测试月退化

**做法**：用 30 个特征（TSFM 分位点、近 3/7/14 日水平/趋势/波动、天气、站点 one-hot、日历）训练 Ridge/HGB，预测 `actual−point` 或 `log1p(actual)−log1p(point)`；再与 RSI 按 25%/50% 混合。使用两个诚实协议：

- 协议 A：训练 ≤2025-08，选参 2025-09，测试 2026-09。
- 协议 B：训练 ≤2026-07，选参 2026-08，测试 2026-09。

**结果**：

| 协议 | 单独校准 | 25% RSI 混合 | 50% RSI 混合 | vs v1 |
|---|---:|---:|---:|---|
| A（2025-09 选参） | 1.842 | 1.762 | 1.778 | +0.015 / +0.031（更差） |
| B（2026-08 选参） | 1.822 | 1.760 | 1.775 | +0.013 / +0.028（更差） |
| 在 2026 上直接选最优（不允许） | 1.720 | — | — | 测试集调参 |

**失败原因**：残差在 2025-09 与 2026-09 之间不可迁移。2025-09 的站间量级差异极大（yanlingwu 20+、jiangjunyan 0.3），模型学到的是“站点水平”，不是“明天残差”；到了 2026-09 低值月份，这些水平项反而有害。即使把 RSI 作为锚点、只混 25%，也只能把校准器的误差部分平均掉，无法超过纯 RSI。

### 4.9 输入/输出变换搜索：dev 上 log1p 最好，测试月反过来

**做法**：TimeRSI 式可执行管线搜索。对 Chronos-2 的输入/输出尝试 `log1p`、`sqrt`、`diff`、`ratio_last`、`ratio_mean7`，在 2025-09 上选变换，应用到 2026-09。

**结果**：

| 变换 | 2025-09 MAE | 2026-09 MAE |
|---|---:|---:|
| log1p | **10.233**（dev 最优） | 1.893 |
| sqrt | 10.349 | 1.880 |
| 原始值 | 10.706 | **1.841** |
| ratio_mean7 | 10.706 | 1.841 |
| ratio_last | 10.706 | 1.847 |
| diff | 11.285 | 1.962 |
| dev 逐站选变换 | — | 1.996 |
| dev 选变换 + 25% raw 混合 | — | 1.796 |

**失败原因**：变换在 dev 上改善的是“高值月份的相对误差”，在测试月低值区间反而放大噪声。这是本轮最清晰的 **dev→test 反转**案例之一。

### 4.10 H3 门控与跨模型融合：v2 已经接近最优

- **H3 在线门控（按 station×horizon，滞后 h 天反馈）**：2.430，差于 v2 2.351。H3 的窗口误差反馈比 H1 更稀疏（每个 horizon 每天只有 1 个新反馈），门控学不到稳定信号。
- **H3 累积门控**：2.349，仅比 v2 好 0.002，实质为零。
- **H3 跨模型 0.5 混合**：2.433，差于 2.351。
- **非因果的“无延迟”门控**：2.235，但它使用了当前窗口尚未揭晓的真值，不能作为结果。

### 4.11 H1 与 H3 day-1 融合：两个版本没有互补性

**做法**：在 H1 与 H3 v2 的 103 个重叠窗口上，混合 `(1−w)·H1 + w·H3_d1`。

**结果**：H1 1.822，H3_d1 1.904；w=0.1 起单调变差，最好就是 w=0（1.822）。全 113 行上 w=0.2 为 1.761，仍差于 v1 的 1.747。

**失败原因**：H3 v2 的 day-1 预测与 H1 v1 使用同一批 TSFM 输出和相似的天气信息；H3 的额外修正没有带来新信息，只增加了噪声。

### 4.12 TimeClaw 结构化经验记忆：尚未运行

**设计**：把 v1 的 ≤400 字自由文本 memory 换成 9 元组规则库（kind / summary / applicability / preferred / avoided / rationale / evidence / confidence / injectable），上限 30 条，按 regime 检索注入，并对“模型选择”做 tool-prior 去偏。

**为什么没跑**：

- 需要完整 H1 LLM 回放（约 90 次 LLM 调用），成本高。
- v1 的模型选择贡献约为 0（几乎总是 chronos2），tool-prior 去偏没有可作用的方差。
- 规则记忆能影响的只剩 fusion 幅度；而本轮的 cap、calibrator、Hedge 都说明“改变 fusion 幅度”在当前信息集下没有稳定收益。
- 113 个样本下，即使有 0.02–0.03 的改善也无法显著。

**结论**：不是“失败”，而是“优先级低”。如果未来扩大测试月或引入未来天气协变量，再跑 TimeClaw 才有意义。

## 5. 为什么这些机制在这里系统性失效

1. **样本量太小**：H1 只有 113 个站-日，MAE 差 0.02–0.03 的 95% CI 宽度约 ±0.04–0.06。任何小于 2% 的改动都无法宣称有效。13 个实验中，大多数“提升”都落在这个噪声带内。
2. **分布漂移**：2025-09 dev 的 MAE 量级是 11.3，2026-09 是 1.75；两月的水平、峰值频率、天气 regime 都不同。多数“在 dev 上选参”的机制（context、变换、校准器）出现了明显反转；H1 v1.1 的在线门控是少数没有反转的例外，但它的 dev 增益只有 0.02，且选参不稳定（见 2.2）。
3. **专家同质且弱**：timesfm3 / seasonal_naive 在 2026-09 并不比 chronos2 好；集成只会把强专家拉向弱专家。FairAMO 的“互补性”前提不成立。
4. **v1 的增益集中在少数大修正**：yanziling 的 −0.354 是 v1 相对 raw 的主要来源。任何 cap、shrinkage、Hedge 都会优先削掉这些大修正，因此必然变差。
5. **门控已经到顶**：v1/raw 的逐样本完美开关上限是 **1.690**，v1.1 的 1.689 已经贴住。继续在 {v1, raw} 之间做选择/修正，理论空间约等于 0。

## 6. 下一步：哪些方向还有真实空间

按预期收益排序：

1. **未来天气协变量**（最高优先级）。当前 H3 的未来 3 天天气依赖预报，历史上存在大量缺失/不可用；如果能把“未来 3 天 Tmax/降水/辐射”作为协变量或作为 LLM 的显式证据，此前统计的约 36% “臆造预报”修正理由才能从根上缓解。这不是 agent 角色问题，而是信息集问题。
2. **扩大评测月份/站点**。当前只有 2026-09 一个月、4 个站。任何 0.02–0.05 的改进都需要更多月份才能验证；建议至少加入 2026-07/08 或 2027 年同月作为外部测试。
3. **区间/覆盖率校准**，而不是继续压点预测。用户主指标是 MAE/RMSE/W-MAE/W-RMSE/PRE；点预测已接近信息集上限，而 H3 的区间覆盖率仍有提升空间（v2 逐站 coverage 0.63–0.81）。
4. **训练式残差校准**只有在扩大训练集、加入未来天气后才值得重试；当前 30 特征 + 765/1101 样本的校准器在诚实协议下全部差于 v1。
5. **不要继续增加 agent 角色**。决策/修正/复盘三角色已经覆盖现有信息源；再拆角色没有新增信息，只会增加 LLM 方差和成本。
